# MASTER PROMPT FOR CODEX — HR Assessment SaaS MVP

Ты senior full-stack engineer и product-minded architect. Работай в существующем проекте или создай новый проект, если репозиторий пустой.

## Цель продукта

Нужно создать MVP SaaS-платформы для оценки кандидатов, похожей по идее на HRScanner, но с более современной архитектурой:

- компании регистрируются в системе;
- HR создает вакансии;
- HR выбирает предустановленный пакет тестов или создает свой тест;
- HR приглашает кандидата по ссылке;
- кандидат заполняет анкету и проходит тесты без регистрации;
- система считает результаты по тестам и компетенциям;
- HR видит отчет по кандидату;
- HR сравнивает кандидатов в рамках одной вакансии;
- система поддерживает предустановленные системные тесты и кастомные тесты компании.

## Важные архитектурные правила

### 1. Версии тестов

Нельзя редактировать опубликованную версию теста. Если HR хочет изменить тест, нужно создать новую версию.

Исключение допускается только для отмены ошибочной публикации последней версии системного теста:

- действие доступно владельцу или администратору платформы;
- версия не должна входить ни в один пакет оценки;
- по версии не должно быть сессий или результатов кандидатов и сотрудников;
- у теста не должно быть другого черновика;
- проверка зависимостей, смена статуса и запись в аудит выполняются атомарно в базе данных.

Если опубликованная версия уже использовалась, ее содержание остается неизменяемым, а для правок создается новая версия.

Сущности:

- test_templates — логический тест;
- test_versions — конкретная опубликованная или черновая версия;
- test_sections — секции внутри версии;
- questions — вопросы;
- answer_options — варианты ответов.

Кандидат всегда проходит конкретный `test_version_id`.

### 2. Сравнение кандидатов

Сравнивать кандидатов нужно в рамках одной вакансии и желательно одного assessment package.

Сохраняй:

- overall_score — общий результат;
- fit_score — соответствие именно этой вакансии;
- rank_position — место среди кандидатов;
- percentile — процентиль;
- risk_level;
- recommendation.

### 3. Вес компетенций

Для каждой вакансии можно задать веса компетенций:

- learning_ability;
- attention_to_detail;
- logical_reasoning;
- work_behavior;
- communication;
- responsibility;
- motivation_fit.

`fit_score` считается по весам вакансии.

### 4. Мотивация

Мотивационный профиль не оценивается как правильно/неправильно. Он должен попадать в профиль кандидата и влиять на рекомендации, но не должен автоматически считаться как ошибка.

### 5. Candidate без аккаунта

Кандидат не должен регистрироваться. Он проходит по защищенному invitation token.

### 6. Privacy

Не используй возраст, пол, национальность, религию, здоровье и другие чувствительные признаки для скоринга. Согласие на обработку данных должно быть на стартовой странице кандидата.

## Алгоритм оценки

### Для вопроса

- single_choice: points выбранного варианта.
- multiple_choice: сумма или exact match, настройка в `settings_json`.
- scale: значение шкалы влияет на competency_effect_json.
- open_text: в MVP без автоматической оценки, статус `requires_review`.

### Для теста

- raw_score = сумма баллов;
- max_score = сумма максимальных баллов;
- percentage = raw_score / max_score * 100.

### Для компетенции

Суммировать эффекты ответов по `competency_key` или `competency_effect_json`.

### Для application

`overall_score` = средневзвешенный результат тестов в assessment package.

`fit_score` = сумма `competency_percentage * job_competency_weight`.

Если обязательная компетенция ниже minimum_score, добавить risk flag и понизить рекомендацию.

## Уровни рекомендаций

- 85–100: strong_candidate
- 75–84: invite
- 65–74: consider
- 50–64: backup
- <50: not_recommended

Если есть high risk flag, рекомендация не должна быть выше `consider`.
