# Подготовка тестов для импорта в Talvia с помощью ИИ

## Назначение

Этот документ помогает получить от ИИ готовый JSON-файл теста для Talvia. Для новых тестов используйте контракт `13_TALVIA_TEST_IMPORT_SCHEMA_V2.json`. Контракт `08_TALVIA_TEST_IMPORT_SCHEMA_V1.json` остается доступен для обратной совместимости.

Один JSON-файл описывает один тест. При импорте Talvia сама назначает UUID, автора и статус. В загрузчике компании создается пользовательский тест этой компании. В административном загрузчике пользователь явно выбирает существующий системный тест с `company_id: null`, а содержимое файла становится его следующей черновой версией. Порядок секций, вопросов и вариантов определяется их порядком в массивах JSON.

ИИ не должен добавлять в файл:

- `id`, UUID и идентификаторы базы данных;
- `company_id` и `created_by`;
- `is_system`;
- статус теста или версии;
- даты создания и публикации.

## Как выбирать версию скоринга

Используйте `talvia.test.v2`, когда результат должен иметь явную модель, профиль шкал, reverse scoring, веса items, thresholds или composites. Объект `test` при этом сохраняет структуру v1, а новый объект `scoring` отдельно описывает интерпретацию ответов.

- Для knowledge и performance-вопросов используйте `scoring_model: "criterion"`; правильность и баллы остаются в содержимом вопроса, а `strategy` должен соответствовать его типу.
- Для personality, behavior и motivation не создавайте искусственные правильные ответы. Используйте scale-вопросы с `scoring_model: "scale"`, `dimension_effects`, `reverse_scored` и `item_weight`. Для профильного результата задавайте `result_shape: "profile"` и `overall_score: null`.
- Для Forced Choice используйте существующий формат вопроса, а в V2 явно сопоставьте каждый `option_key` со шкалой в `statements`. Модель `ipsative` сохраняет расчет MOST минус LEAST; `thurstonian_irt` зарезервирован и не публикуется.
- Для knowledge-уровней задавайте полный упорядоченный массив `thresholds`, покрывающий 0–100 без пересечений. Если он отсутствует, применяются legacy-уровни совместимости.
- Не выдавайте normalized score за percentile, sten или norm score. `norm_assignments` допустимы только при наличии реального опубликованного набора норм точной версии.
- Для learning обязательно сохраняйте связь исходного `single_choice` с feedback и recovery-вопросом через `remediation_question_key`, задавайте `assessment_domain: "learning"`, `learning_scoring` и направляйте `overall_score` на criterion `learning_final`. Веса `initial_weight` и `recovery_weight` должны суммироваться в 1.

Каждый автоматически оцениваемый вопрос V2 должен иметь ровно один элемент `scoring.items` с тем же `question_key`; `open_text` не должен иметь автоматический scoring item. Все ссылки на dimensions, composites и option keys проверяются до записи в базу.

## Как получить файл от ИИ

1. Для нового теста приложите `13_TALVIA_TEST_IMPORT_SCHEMA_V2.json` и этот документ. Используйте `08_TALVIA_TEST_IMPORT_SCHEMA_V1.json` только для legacy-импорта.
2. Заполните промпт из следующего раздела.
3. Попросите ИИ вернуть только содержимое JSON-файла.
4. Сохраните ответ в кодировке UTF-8 с расширением `.json`.
5. Перед импортом проверьте содержание теста, правильные ответы, баллы и отсутствие чувствительных критериев оценки.

Все содержательные строки должны быть обычным текстом без HTML и служебного префикса форматирования Talvia. Перед проверкой ограничений Talvia должна обрезать пробелы по краям строк.

## Соответствие полей модели Talvia

| Поле файла | Назначение в Talvia |
| --- | --- |
| `test.title` | Название нового шаблона компании; при системном импорте используется для сверки в предпросмотре и не переименовывает выбранный шаблон |
| `test.category` | Категория шаблона, до 100 символов |
| `test.description` | Описание шаблона и начальной черновой версии, до 2000 символов |
| `test.instructions` | Инструкция начальной черновой версии |
| `test.duration_minutes` | Длительность начальной черновой версии |
| `test.scoring_type` | Тип оценки начальной черновой версии |
| `test.presentation` | Настройки показа, сохраняемые в `settings_json` версии |
| Порядок элементов в массивах | `order_index`, начиная с 1 |
| `key` | Только локальный ключ для проверки файла; в базу не переносится |
| `remediation_question_key` | Локальный `key` повторного вопроса после ошибки; при импорте преобразуется во внутренний UUID |
| `incorrect_feedback` | Объяснение, которое кандидат увидит после неверного ответа перед повторным вопросом |

Для `single_choice` Talvia записывает в `questions.points` максимальное значение `points` среди вариантов. Для `ordering` и `matching` максимальный балл задается полем вопроса `points`. Для `scale` внутренний максимальный балл равен `scale.max`. Для `open_text` автоматический балл не назначается.

Лимит времени отдельной секции намеренно не входит в `talvia.test.v1`: сейчас прохождение Talvia надежно применяет общий `duration_minutes`, а сохраненное поле лимита секции еще не участвует в candidate flow.

## Готовый промпт для `talvia.test.v2`

```text
Подготовь один новый тест для импорта в Talvia строго по приложенной JSON Schema v2.

Тема и целевая должность: [указать]
Цель оценки: [knowledge / skills / personality / motivation / behavior]
Желаемый результат: [score / profile / hybrid]
Количество вопросов и длительность: [указать]
Измеряемые dimensions: [указать стабильные ключи и названия]

Требования:
- верни только валидный JSON с schema_version "talvia.test.v2";
- не добавляй поля, отсутствующие в JSON Schema;
- каждому автоматически оцениваемому question_key сопоставь ровно один scoring item;
- для criterion выбери strategy, соответствующую типу вопроса;
- для profile используй scale item, dimension_effects, явные границы ответа и осмысленно чередуй direct/reverse_scored items;
- не используй is_correct как основу personality, behavior или motivation profile;
- item_weight должен быть положительным, default — 1;
- для profile установи test.scoring_type "competency_profile", result_shape "profile" и overall_score null;
- для score установи test.scoring_type "points", result_shape "score" и явно сопоставь overall_score;
- если задаешь thresholds, полностью покрой 0..100 упорядоченными непересекающимися диапазонами;
- не генерируй percentile, sten или нормативы без предоставленного опубликованного norm set;
- для Forced Choice сопоставь каждый option_key ровно один раз и используй method "ipsative";
- для learning используй criterion items с min_points 0, добавь минимум одну remediation-пару и установи overall_score в {"source_type":"criterion","source_key":"learning_final"};
- все key должны быть уникальными, стабильными и машиночитаемыми;
- не используй чувствительные признаки кандидата в вопросах или scoring.
```

## Legacy-промпт для `talvia.test.v1`

```text
Подготовь один тест для импорта в Talvia по приложенной JSON Schema.

Название или тема теста: [указать]
Целевая должность: [указать]
Цель оценки: [указать]
Количество вопросов: [указать]
Ожидаемая продолжительность: [указать] минут
Типы вопросов: [single_choice, scale, open_text, forced_choice, ordering и/или matching]
Проверяемые компетенции: [указать ключи из разрешенного списка]
Желаемая сложность: [easy, medium, hard или сочетание]
Дополнительный контекст компании или должности: [указать либо написать «нет»]

Требования:
- используй schema_version "talvia.test.v1";
- верни один тест и минимум одну секцию;
- используй только поля и значения, разрешенные схемой;
- все локальные key должны быть уникальными во всем файле;
- key пиши латиницей в нижнем регистре, например section_1, q_001, q_001_a;
- category оформи как короткий английский ключ в нижнем регистре, например sales_basics;
- выбери scoring_type строго по составу вопросов: только open_text — manual; open_text вместе с другими типами — mixed; forced_choice вместе с single_choice, multiple_choice, ordering или matching без open_text — mixed; scale и/или forced_choice без сочетания forced_choice с балльными вопросами и без open_text — competency_profile; только single_choice, multiple_choice, ordering и/или matching — points или competency_profile;
- для single_choice создай от 2 до 6 содержательных вариантов ответа;
- для single_choice отметь ровно один лучший вариант как is_correct: true;
- правильный вариант должен быть единственным вариантом с максимальным количеством points;
- если после неверного ответа нужен повторный вопрос, укажи у исходного single_choice поля incorrect_feedback и remediation_question_key; повторный вопрос размести ниже исходного в той же секции;
- remediation_question_key должен ссылаться на key существующего вопроса; один повторный вопрос нельзя использовать для нескольких исходных вопросов, а повторный вопрос не должен открывать следующую ветку после ошибки;
- для forced_choice добавь объект "forced_choice": {"mode": "most_least"} и создай минимум 3 содержательных утверждения, из которых кандидат выбирает два разных: «больше всего» и «меньше всего»;
- для forced_choice укажи competency_key: null, а у каждого варианта — непустой competency_effects с положительными значениями; не добавляй в варианты is_correct и points;
- учти, что forced_choice оценивает профиль по модели Best–Worst: выбор «больше всего» добавляет эффект, а «меньше всего» вычитает его; формулируй утверждения как сопоставимые по привлекательности и без явно «правильного» ответа;
- для ordering перечисли правильную последовательность в массиве items, задай points > 0 и ordering.scoring_mode = pairwise для частичного балла или exact для балла только за полностью верный порядок;
- для matching перечисли однозначные пары left/right в массиве pairs, задай points > 0 и matching.scoring_mode = per_pair для частичного балла или exact для балла только за полностью верное сопоставление;
- points не должны быть отрицательными, а заполненный эффект компетенции должен быть положительным;
- points и значения competency_effects указывай максимум с двумя знаками после запятой;
- для scale по умолчанию используй диапазон 1–5 и формулируй утверждения прямо: большее значение всегда означает более сильное проявление указанной компетенции или предпочтения;
- не создавай обратные scale-утверждения, потому что talvia.test.v1 не поддерживает reverse scoring;
- не делай правильный ответ заметно длиннее или подробнее остальных;
- не используй неоднозначные формулировки без необходимого контекста;
- используй обычный текст без HTML и Markdown внутри строк;
- для необязательного пустого текста используй null, а не пустую строку;
- не используй возраст, пол, национальность, религию, здоровье, семейное положение, политические взгляды и другие чувствительные признаки для оценки;
- не делай медицинских, клинических или психологических диагнозов;
- не добавляй UUID, company_id, created_by, is_system, status и даты;
- верни только валидный JSON без Markdown, комментариев и пояснений до или после JSON.
```

## Поддерживаемые типы вопросов в версии 1

### `single_choice`

Один вариант ответа. Talvia автоматически начисляет `points` выбранного варианта. Максимальный балл вопроса определяется по наибольшему значению `points` среди вариантов.

Правила:

- минимум два варианта;
- ровно один вариант с `is_correct: true`;
- правильный вариант единственный получает максимальный балл;
- `points` не могут быть отрицательными;
- `points` и эффекты задаются с точностью не более двух знаков после запятой;
- заполненное значение в `competency_effects` должно быть больше нуля; отсутствие эффекта обозначается пустым объектом `{}`;
- один вариант ответа может содержать эффект только одной компетенции, как и в текущем конструкторе Talvia;
- `explanation` содержит комментарий для HR, не показывается кандидату во время прохождения и может быть `null`.
- необязательные `incorrect_feedback` и `remediation_question_key` задают ветку с повторным вопросом после ошибки; если ветка не нужна, оба поля можно не добавлять или передать как `null`.
- `shuffle_options: true` включает стабильное перемешивание вариантов для каждой попытки; если поле отсутствует, используется `false`.

Есть два взаимоисключающих способа связать вопрос с компетенциями:

1. Простой способ: задать `competency_key` у вопроса, а во всех вариантах оставить `competency_effects: {}`.
2. Многомерный способ: задать у вопроса `competency_key: null`, а эффекты указать в `competency_effects` вариантов.

Не смешивайте эти способы в одном вопросе. Если хотя бы у одного варианта заполнен `competency_effects`, Talvia использует эффекты вариантов вместо `competency_key` вопроса.

### `multiple_choice`

Несколько вариантов ответа. Укажите `selection.min`, `selection.max` и одну из трех стратегий:

- `exact_match`: полный балл получает только набор, точно совпавший с вариантами `is_correct: true`; веса вариантов равны нулю;
- `partial_credit`: каждый правильный выбор добавляет `correct_option_points`, а неверный при `penalty_mode: "subtract"` вычитает `incorrect_option_penalty`; итог ограничивается `min_points` и `max_points`;
- `option_points`: итог — сумма signed `points` выбранных вариантов с floor/cap; бинарный feedback определяется только `correctness_threshold`, а `is_correct` у вариантов всегда `null`.

`required: true` требует `selection.min >= 1`, для необязательного вопроса `selection.min` равен нулю. `selection.max` задаёт автор и не раскрывает количество правильных вариантов. Полный пример всех режимов находится в `docs/11_MULTIPLE_CHOICE_EXAMPLES.json`.

Для `multiple_choice` также можно указать `shuffle_options: true`. Перемешивание меняет только показ вариантов; ответ и scoring всегда используют внутренние ID вариантов.

### Повторный вопрос после ошибки

Ветка после ошибки поддерживается у исходного вопроса `single_choice` или `multiple_choice`. Для нее укажите вместе два поля:

- `incorrect_feedback` — понятное объяснение ошибки без раскрытия лишних служебных данных;
- `remediation_question_key` — локальный `key` вопроса, который кандидат должен пройти после неверного ответа.

Повторный вопрос является обычным вопросом в массиве `questions`, но должен находиться ниже исходного вопроса в той же секции. Если кандидат ответил правильно, Talvia пропускает связанный повторный вопрос. После неверного ответа Talvia показывает `incorrect_feedback`, а затем открывает повторный вопрос.

Ограничения:

- один повторный вопрос может быть связан только с одним исходным вопросом;
- повторный вопрос сам не может открывать еще одну ветку после ошибки;
- ссылка задается через локальный `key`, а не через UUID;
- оба поля должны быть заполнены вместе;
- импорт преобразует локальный ключ во внутренний `remediationQuestionId` только после создания всех вопросов;
- при нарушении связи импорт блокируется целиком и не создает частичный тест.

Пример:

```json
{
  "key": "q_001",
  "type": "single_choice",
  "text": "Какое действие нужно выполнить первым?",
  "description": null,
  "required": true,
  "difficulty": "easy",
  "competency_key": "learning_ability",
  "incorrect_feedback": "Сначала примените правило приоритета из инструкции.",
  "remediation_question_key": "q_001_retry",
  "options": [
    {
      "key": "q_001_a",
      "text": "Проверить приоритет",
      "is_correct": true,
      "points": 1,
      "competency_effects": {},
      "explanation": null
    },
    {
      "key": "q_001_b",
      "text": "Сразу закрыть заявку",
      "is_correct": false,
      "points": 0,
      "competency_effects": {},
      "explanation": null
    }
  ]
}
```

Ниже этого объекта в том же массиве `questions` должен находиться вопрос с `"key": "q_001_retry"`.

### `scale`

Числовая шкала без правильного и неправильного ответа. Для шкалы обязательна одна компетенция в `competency_key`.

Пример фрагмента:

```json
{
  "key": "q_002",
  "type": "scale",
  "text": "Мне комфортно самостоятельно выбирать способ выполнения задачи.",
  "description": "1 — полностью не согласен, 5 — полностью согласен.",
  "required": true,
  "difficulty": null,
  "competency_key": "motivation_autonomy",
  "scale": {
    "min": 1,
    "max": 5
  }
}
```

Шкалы без `open_text` должны использоваться в тестах с `scoring_type: "competency_profile"`. Talvia рассчитывает процент шкалы как `выбранное значение / scale.max × 100`: для шкалы 1–5 это 20%, 40%, 60%, 80% и 100%. Обратного подсчета нет, поэтому большее значение всегда должно означать более сильное проявление компетенции или предпочтения.

Не смешивайте мотивационные шкалы с заданиями на знания или внимательность. Для такого содержания лучше создавать отдельные тесты, чтобы профиль не воспринимался как оценка правильности.

### Motivation / Forced Choice

Для мотивационного профиля используйте вопросы `forced_choice` с режимом `most_least` и `scoring_type: "competency_profile"`. В каждом блоке должно быть минимум три сопоставимых утверждения без правильного и неправильного ответа. Один вариант обычно воздействует ровно на одну мотивационную шкалу положительным значением в `competency_effects`.

Talvia применяет MVP Best–Worst scoring: выбранное как «Больше всего» утверждение добавляет эффект, выбранное как «Меньше всего» — вычитает его, а остальные утверждения дают нулевой вклад. Компетенция определяется только по `competency_effects` варианта и не должна зависеть от его позиции в массиве или на экране. Исходный выбор MOST/LEAST сохраняется отдельно для возможной будущей психометрической калибровки.

Для Talvia Motivation-9 FC используйте только эти девять ключей:

- `motivation_result` — результат;
- `motivation_growth` — развитие;
- `motivation_autonomy` — автономия;
- `motivation_influence` — влияние;
- `motivation_team` — команда;
- `motivation_stability` — стабильность;
- `motivation_income` — вознаграждение;
- `motivation_recognition` — признание;
- `motivation_meaning` — смысл.

`motivation_structure` остается допустимой legacy/дополнительной шкалой для обратной совместимости, но не входит в Motivation-9. Не смешивайте ключи `motivation_*` с `work_*`: источники мотивации и рабочее поведение — разные конструкты. Мотивационный профиль не участвует в pass/fail, автоматическом отказе, общем профессиональном `fit_score`, минимальных порогах и risk flags.

### `ordering`

Сортировка проверяет правильный порядок элементов. Порядок объектов в `items` является эталонным. Кандидату Talvia показывает элементы в перемешанном порядке.

- `points` — максимальный балл вопроса;
- `ordering.scoring_mode: "pairwise"` начисляет долю балла за каждую верно сохраненную относительную пару элементов;
- `ordering.scoring_mode: "exact"` начисляет весь балл только за полностью правильный порядок;
- тексты элементов и все `key` должны быть уникальными.

```json
{
  "key": "q_ordering_1",
  "type": "ordering",
  "text": "Расположите этапы обработки обращения.",
  "description": null,
  "required": true,
  "difficulty": "medium",
  "competency_key": "work_organization",
  "points": 4,
  "ordering": { "scoring_mode": "pairwise" },
  "items": [
    { "key": "q_ordering_1_a", "text": "Уточнить запрос" },
    { "key": "q_ordering_1_b", "text": "Предложить решение" },
    { "key": "q_ordering_1_c", "text": "Зафиксировать результат" }
  ]
}
```

### `matching`

Сопоставление проверяет однозначные пары. Объекты в `pairs` задают эталонную связь `left` → `right`; правые значения при прохождении перемешиваются отдельно.

- `points` — максимальный балл вопроса;
- `matching.scoring_mode: "per_pair"` начисляет равную долю балла за каждую верную пару;
- `matching.scoring_mode: "exact"` начисляет весь балл только за полностью верное сопоставление;
- левые и правые значения не должны повторяться внутри вопроса.

```json
{
  "key": "q_matching_1",
  "type": "matching",
  "text": "Сопоставьте термин и определение.",
  "description": null,
  "required": true,
  "difficulty": "easy",
  "competency_key": "learning_ability",
  "points": 3,
  "matching": { "scoring_mode": "per_pair" },
  "pairs": [
    { "key": "q_matching_1_a", "left": "SLA", "right": "Срок предоставления сервиса" },
    { "key": "q_matching_1_b", "left": "CRM", "right": "Система работы с клиентами" }
  ]
}
```

### `open_text`

Свободный текстовый ответ. Он не оценивается автоматически и переводит результат в режим, требующий ручной проверки.

Пример фрагмента:

```json
{
  "key": "q_003",
  "type": "open_text",
  "text": "Опишите, как вы проверяете работу перед передачей клиенту.",
  "description": null,
  "required": true,
  "difficulty": "medium",
  "competency_key": "responsibility"
}
```

Если тест содержит открытые вопросы вместе с автоматически оцениваемыми, используйте `scoring_type: "mixed"`. Если все вопросы открытые — `scoring_type: "manual"`.

Сейчас Talvia сохраняет и показывает открытые ответы HR, но не позволяет назначить им ручные баллы или закрыть состояние проверки. Поэтому наличие хотя бы одного `open_text` оставляет всю оценку с рекомендацией `requires_review` и исключает этот тест из `overall_score`.

`competency_key` у `open_text` используется только как метка для HR и не создает числовой результат по компетенции.

Новые `multiple_choice` импортируются с явной стратегией scoring version 1. Уже опубликованные legacy-вопросы без этого marker не пересчитываются автоматически и остаются `requires_review`.

## Влияние `scoring_type` на результат

| Значение | Фактическое поведение Talvia |
| --- | --- |
| `points` | Автоматический процент теста участвует в `overall_score`; компетенции могут участвовать в `fit_score` |
| `competency_profile` | Профиль сохраняется по компетенциям, но процент теста исключается из `overall_score` |
| `manual` | Результат получает `requires_review` и исключается из `overall_score` |
| `mixed` | Используется при сочетании `open_text` с автоматическими вопросами; из-за ручной проверки весь тест исключается из `overall_score` |

Мотивационные компетенции `motivation_*` сохраняются как профиль, но не влияют на `fit_score`, минимальные пороги, риски и сильные стороны. Это соответствует текущему правилу Talvia: мотивацию нельзя оценивать как правильную или неправильную без целевого профиля вакансии.

## Дополнительные проверки Talvia при импорте

JSON Schema проверяет форму документа, но импорт должен дополнительно проверять бизнес-правила:

- уникальность всех `key` во всем файле;
- `scale.min < scale.max`;
- ровно один правильный вариант у каждого `single_choice`;
- правильный вариант единственный имеет максимальное количество баллов;
- максимальный балл каждого автоматически оцениваемого вопроса больше нуля;
- у `ordering` минимум два уникальных элемента, а у `matching` минимум две пары с уникальными левыми и правыми значениями;
- `competency_key` вопроса не смешан с непустыми `competency_effects` вариантов;
- каждый заполненный эффект компетенции положителен, а один вариант содержит не более одного эффекта;
- все строки после удаления пробелов по краям соответствуют минимальной и максимальной длине;
- `scoring_type` соответствует фактическому набору типов вопросов;
- баллы и эффекты имеют не более двух знаков после запятой; это серверная бизнес-проверка, а не `multipleOf: 0.01`, чтобы избежать ошибок двоичной арифметики с корректными значениями вроде `0.07`;
- `incorrect_feedback` и `remediation_question_key` заполнены вместе;
- повторный вопрос существует, расположен ниже исходного вопроса в той же секции, связан только с одним исходным вопросом и сам не открывает следующую ветку после ошибки;

Отдельно как предупреждения для обязательной проверки человеком:

- количество и сложность вопросов реалистично соответствуют общей длительности теста;
- в тексте и скоринге нет чувствительных или дискриминационных критериев;
- задания, правильные ответы и объяснения фактически корректны и однозначны;
- содержимое является оригинальным и не копирует закрытые или лицензируемые методики.

Импорт должен выполняться атомарно: при любой блокирующей ошибке тест не создается частично.

После успешной проверки пользователь должен увидеть предпросмотр и явно подтвердить создание черновика.

## Обязательные требования к загрузчику Talvia

- Авторитетная проверка файла выполняется на сервере, даже если предварительная проверка уже была выполнена в браузере.
- Загрузчик компании проверяет активную компанию, роль пользователя и право компании создавать пользовательские тесты; административный загрузчик допускает только активных `platform_owner` и `platform_admin`.
- `company_id`, `created_by` и остальные служебные значения берутся только из доверенного серверного контекста, а не из загруженного файла.
- Загрузчик компании назначает `company_id` активной компании и `is_system: false`. Административный загрузчик не создает шаблон: он принимает идентификатор явно выбранного системного шаблона с `company_id: null` и `is_system: true`, проверяет совпадение категории и добавляет следующую версию со статусом `draft`.
- Если у системного теста уже есть черновик, импорт новой версии блокируется до публикации или архивирования существующего черновика.
- Импорт системного теста не выдает доступ компаниям: публикация и записи `company_system_test_access` создаются отдельными административными действиями после проверки.
- Шаблон, версия, секции, вопросы и варианты создаются одной транзакцией или одной атомарной серверной операцией.
- Для повторных вопросов загрузчик сначала создает все вопросы, затем внутри той же атомарной операции преобразует `remediation_question_key` во внутренний UUID и сохраняет `incorrectFeedback` и `remediationQuestionId` в настройках исходного вопроса.
- Перед записью строки нормализуются и очищаются; пустые необязательные строки преобразуются в `null`, а неизвестные поля не игнорируются и возвращаются пользователю как ошибки.
- Парсер отклоняет повторяющиеся имена свойств внутри одного JSON-объекта, а также проверяет общий размер файла и суммарное количество секций, вопросов и вариантов до записи в базу.
- Один файл не должен превышать 750 КБ и может содержать не более 100 секций, 300 вопросов суммарно и 3000 вариантов ответа суммарно.
- Ошибки показываются с путем до поля, например `test.sections[0].questions[2].options[1].points`.
- Предпросмотр не должен записывать частичные данные в рабочие таблицы.
