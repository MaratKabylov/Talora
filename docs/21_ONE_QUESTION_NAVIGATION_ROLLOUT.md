# PERF-005a: переход между секциями без перезагрузки

## Реализовано — 07.09.2026

Только режим `one_question`, единая реализация для candidate и employee. Первое открытие
сохраняет серверные проверки overview/section. Последующие переходы внутри той же сессии
получают snapshot через `POST /api/assessment/section`: один section-read RPC, без чтения
overview и повторного claim. Это подсчет обращений в коде/тестах, не измеренное ускорение.
Сохранение ответа выполняется отдельно через существующий session-control API.

`AssessmentTestSession` остается смонтированным. Сохраняются client/device identity,
deadline, интервал heartbeat и session-level состояние. Содержимое, ответы, локальный
учет времени вопросов и прогресс секции заменяются только после успешной загрузки.
При размонтировании или терминальном redirect незавершенный запрос секции отменяется.

Endpoint проверяет формат параметров и Origin, использует существующий server-only reader
с проверками token/tenant/consent/статуса. Все ответы — `private, no-store`. Ошибка RPC
не вызывает legacy fallback и не раскрывает SQL/token. Snapshot проходит существующий
безопасный presenter; scoring metadata и серверные ключи в браузер не добавлены.

## Поведение навигации и сохранения

- Ответ подтверждается сервером до перехода. Повторный клик во время сохранения/загрузки
  не отправляет второе сохранение. Форма временно недоступна для изменения.
- В этом режиме структурированные поля также сохраняются кнопкой подтверждения, без
  параллельного фонового autosave. Это исключает гонку частичного ответа с finalize.
  Неподтвержденный ввод не переживает reload/закрытие вкладки; это не offline-хранилище.
- При ошибке сохранения или загрузки старый ввод остается на экране; переход можно повторить.
  Если сохранение уже прошло, повторный finalize использует прежний идемпотентный upsert.
- URL обновляется через History API. Back/forward внутри текущего test path загружают
  свежую секцию, без кеша ответов. При `allowBack=true` переход к предыдущей секции включает
  review, иначе SQL вернул бы первую незавершенную секцию.
- При `allowBack=false` возврат к прошлой секции блокируется. Несохраненный ввод также
  блокирует внутренний переход до подтверждения; URL восстанавливается к текущей секции.
  Возврат не реализует историю каждого вопроса: история ведется по секциям.
- Переход на другой маршрут, завершение и переход к следующему тесту используют старый
  механизм. Browser back за пределы текущего test path остается ответственностью Next.js.

Применен документированный [Native History API Next.js](https://nextjs.org/docs/app/getting-started/linking-and-navigating#native-history-api).
Локальная browser fixture проверяет React-компоненты, но не заменяет проверку интеграции
History API с настоящим App Router на staging.

## Включение и откат

1. Новая миграция **не нужна**. Должна быть установлена ранее подготовленная
   `20260906140000_assessment_section_read_v2.sql`; проверить ее read-only скриптом
   `supabase/verification/assessment_section_read_v2.sql`. Не запускать тестовые fixtures в Supabase.
2. На staging установить серверные `ASSESSMENT_SECTION_READ_V2=true` и
   `ASSESSMENT_SOFT_NAVIGATION_V2=true`, перезапустить/переопубликовать приложение.
   Выбрать тест с `presentationMode=one_question`. Префикс `NEXT_PUBLIC_` не использовать.
3. `ASSESSMENT_OVERVIEW_V2=true` рекомендуется для компактной первой загрузки, но для
   мягкого перехода не обязателен; требует своей миграции из PERF-004b.
   `SESSION_CONTROL_V2` независим: новый переход использует прежний контракт сохранения.
4. Выполнить приемку ниже до production. Агент не включал реальные флаги и не менял удаленную БД.
5. Откат: `ASSESSMENT_SOFT_NAVIGATION_V2=false` и перезапуск runtime. Новые открытия вернутся
   к старой навигации. Уже открытая V2-вкладка получит ошибку загрузки секции: подтвердить
   текущий ответ и обновить страницу. Схему/данные откатывать не требуется.

## Локальные проверки

- `npm test`: проверки route handler, POST/no-store/abort-контракта, безопасных ошибок,
  выбора видимого вопроса и всех сочетаний read/navigation-флагов и presentation mode
  на обеих реальных страницах. Существующие SQL/reader/lease/scoring тесты сохранены.
- `npm run typecheck`, `npm run lint`, `npm run build`.
- `npm run test:browser:navigation`: собирает реальные React-компоненты в изолированную
  fixture и запускает localhost:4318. Открыть адрес в браузере, дождаться
  `PASS: 4 browser scenarios`; остановить сервер Ctrl+C. Сборка и временные профили
  находятся в игнорируемом `coverage/`. Реальные env/ключи/DB fixture не использует.

В headless Chrome проверены candidate/employee × allowBack true/false: ошибки сохранения
и чтения, сохранность ввода, двойной клик, URL и back/forward, восстановление ответа,
постоянство timer DOM/client/device, один claim, отсутствие пересоздания heartbeat interval,
отмена незавершенного чтения. Transport синтетический, открытый текст — тестовый тип вопроса.
Это browser-component тесты, **не полный Next.js/Supabase E2E**.

## Приемка на staging

Для обоих scope и обоих значений `allowBack` проверить:

1. Первую загрузку, 3+ секции, несколько вопросов в секции, review, Back/Forward,
   reload текущего URL, пустую секцию, remediation и восстановление всех типов ответов.
2. Отказ/задержку save и section API, двойной клик, offline/online, уход со страницы
   во время запроса. Неподтвержденный ответ не теряется при внутреннем переходе.
3. Работающий deadline/heartbeat через несколько переходов, истечение срока,
   конкурентную вкладку/takeover, отмененное приглашение. Запись остается защищена lease.
4. Завершение последней секции, scoring и следующий тест; отдельно legacy section-mode
   при включенном флаге. Проверить оба значения `SESSION_CONTROL_V2`.
5. В настоящем Next.js Network trace: обычный переход не создает Document/RSC-загрузки
   test page, не перечитывает overview, вызывает один section-read RPC после finalize.
   Первый claim не повторяется. Не экспортировать trace с реальными токенами/ответами.
6. Сравнить 30+ cold/warm замеров. Новая клиентская метрика
   `assessment.section_navigation` измеряет загрузку/применение snapshot после finalize,
   **не** полное время от клика и не время до отрисованного кадра. Сохранение измеряется
   отдельно; для пользовательской задержки дополнительно измерить click-to-visible.
   Зафиксировать p50/p95, ошибки, commit, регион/RTT в `docs/17_PERFORMANCE_BASELINE.md`.

## Остаток PERF-004/005

Предзагрузка не реализована: существующий RPC для `one_question` выбирает первую
незавершенную секцию. Преждевременный запрос следующей вернул бы текущую; обход этого
ограничения без отдельного безопасного контракта недопустим.

Отдельными шагами остаются мягкий переход режима целой секции с пакетным сохранением,
prefetch и завершение/смена теста. До этих работ и staging-приемки весь PERF-005 не закрыт.
