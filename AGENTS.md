# AGENTS.md — HR Assessment SaaS MVP

Ты работаешь над MVP SaaS-платформы для оценки кандидатов.

Перед началом работы обязательно прочитай:

- `docs/01_PRODUCT_SPEC_MVP.md`

## Цель продукта

Создать MVP платформы, где компании могут:

- создавать вакансии;
- использовать предустановленные тесты;
- создавать свои тесты;
- приглашать кандидатов по ссылке;
- получать отчет по кандидату;
- сравнивать кандидатов в рамках вакансии.

## Архитектурные правила

1. Система должна быть multi-tenant.
2. Почти все бизнес-таблицы должны иметь `company_id`.
3. Данные компаний должны быть изолированы через RLS.
4. Кандидат проходит тест по invitation token без регистрации.
5. Опубликованные версии тестов нельзя редактировать.
6. При изменении теста создается новая версия.
7. Результаты кандидата всегда должны ссылаться на конкретный `test_version_id`.
8. Сравнение кандидатов выполняется в рамках одной вакансии.
9. Должны быть `overall_score` и `fit_score`.
10. Не использовать чувствительные признаки кандидата для скоринга.

## MVP-приоритет

Сначала реализуй:

1. Bootstrap проекта.
2. Supabase schema.
3. Auth и компанию.
4. Вакансии.
5. Кандидаты.
6. Тесты и версии тестов.
7. Candidate flow по token-ссылке.
8. Scoring.
9. Отчеты.
10. Сравнение кандидатов.

## Как работать

- Не пытайся сделать весь проект за один шаг.
- Работай по milestone из `docs/04_BACKLOG.md`.
- Перед изменениями сначала изучи структуру проекта.
- После каждого крупного изменения запускай lint/typecheck/build, если команды доступны.
- Если нужны переменные окружения, добавь `.env.example`, но не придумывай реальные ключи.
- Не храни Supabase service role key на клиенте.
